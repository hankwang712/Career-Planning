# 招聘雷达移植

独立测试台与主站多智能体报告统一使用招聘雷达。旧的搜狗微信搜索实现、Agent分支及渠道选择入口已移除；历史请求或检查点中的旧渠道值会迁移为 `radar`，不会重新调用旧搜索。

## 启动与入口

沿用现有依赖及 `.env` 模型配置：

```powershell
D:/anaconda3/envs/yolov11/python.exe backend/tools/recruitment_lab/app.py
```

- Agent 测试台：<http://127.0.0.1:8766/>
- 数据工作台：<http://127.0.0.1:8766/radar>

## 已移植并接入

1. 856个企业官网、公开节点和固定公众号文章地址，支持行业筛选与分批并发采集。
2. 腾讯文档两个公开招聘表的解压、字段解析及累计分页同步。保留来源更新日期、官方公告、招聘批次、岗位、城市、截止日期和投递链接。第一表最多900行，第二表最多6000行；触及上限会说明覆盖限制。同步后缓存6小时，工作台可手动强制同步。
3. 仓库的1598条历史快照作为首次离线兜底，明确标注2026-09-03，不当作最新公告。实时数据保存在 `data/app_data/recruitment-radar/`，不会覆盖上游快照。
4. 官网正文直接读取；不足时使用已配置的Firecrawl、AnySearch补充。Agent候选详情还可使用本机Chrome渲染兜底（需连接现有CDP服务，可设 `RADAR_BROWSER_FALLBACK=0` 关闭）；浏览器访问逐页进行，验证页保留给用户，不自动破解。先从汇总表做语义初筛，再对相关候选集中读取，最多8条；公告读取受阻时可尝试该记录已有的官网投递链接，每条最多两个入口。HTTP最多3个并发，相同公告复用读取结果。工作台每次可选1—856个节点采集，已获取数据持续保存。
5. 工作台分页20/50/100条、公司/岗位/城市/行业/来源筛选、节点目录、逐条原始记录及已读正文、JSON/CSV导入导出、取消采集。
6. BrowserAct/OpenCLI导出文件通过导入入口落库，Agent检索会一起使用。JSON支持数组或 `jobs/items/data` 数组包装，CSV支持中文及常见英文字段。
7. 默认Agent先理解用户条件，召回招聘记录并做语义初筛，再优先读取相关候选的公告和投递页，最后依据新正文复核，通常3次模型调用。职位短语完整匹配优先于零散关键词共现，同等相关度优先近期更新的记录。模型和工具预算不足时明确保留限制。
8. 前端分别显示岗位相关性、原文读取、发布时间及投递入口，不再把所有状态都标成一串“未核实”。同类日期、职责提示合并；岗位是否仍开放作为公共限制，不会单独使已确认的查询条件失效。用户明确要求近期时，已知超出时间范围的公告只放在排除记录，不能继续充作推荐；未知日期仍如实保留。来源更新日、采集日不冒充公告发布日期。
9. 多智能体的并行招聘分支、用户补充后的修订及旧检查点恢复共用此Agent。职业决策可使用带证据等级的招聘汇总线索作为机会背景；尚未读到岗位全文的记录强制标注待确认，不能作为岗位职责或任职资格事实。报告附录保留来源类型、日期和具体缺项。

同步失败保留上一份数据；官网下载失败保留招聘线索。网站要求登录、验证或依赖复杂客户端时不声称已取得正文。

## 需要额外配置、尚不能保证的能力

- Firecrawl：服务端设置自己的 `RADAR_FIRECRAWL_API_KEY` 或 `FIRECRAWL_API_KEY`。不使用上游内置共享Key。
- AnySearch：服务端设置 `ANYSEARCH_API_KEY`，或 `RADAR_ANYSEARCH_ENABLED=1` 尝试匿名接口。通过服务端直连，不经公共CORS代理。配额和实际可用性取决于供应商，未配置时不会假装备用服务已运行。
- BrowserAct/OpenCLI：需要另外安装、登录及准备适配器。上游当前提交没有README声称的 `clis/xiaozhao/` 代码，所以本移植支持其文件导入，不声称已实现一键运行这些CLI。
- 不自动解验证码，不保证私有/登录态岗位库或微信内搜一搜全量覆盖。16个公众号节点是固定文章，并非公众号历史文章全量订阅。
- 默认不会自动抓完856个网站；可在工作台调整节点上限，控制等待时间和云服务费用。

可将额外服务配置写入 `.env`，随后重启测试服务；密钥只在服务端使用。

主站后台报告会在不同线程和事件循环中运行，数据同步、落盘和浏览器资源使用跨事件循环的锁；暂停或取消时会等待已发出的浏览器读取完成清理。
