# 统一职业档案

个人中心默认进入「职业档案」，包含档案概览、技能与证据、职业目标、测评与简历四个分类。规划报告、学习路径、账户设置保留为独立入口。固定通知数字和重复的隐藏学习面板已移除；API 配置与账户管理仅对管理员显示。

## 数据结构

沿用应用的 SQLite 数据库 `data/app_data/app.db`，启动时通过 `init_db()` 创建新表，不重写既有用户空间。每条记录都有独立 ID、账户外键、来源类型、来源引用、创建时间、更新时间和版本号。

| 模型 | 表 | 说明 |
| --- | --- | --- |
| UserProfile | career_profiles | 每个用户一份基础职业画像；姓名、职业定位、城市、阶段、简介为独立列 |
| ProfileEntry | career_entries | 教育、经历、证书、兴趣、求职偏好按条目维护 |
| UserSkill | career_skills | 每项技能独立存储，同一账户内名称忽略大小写去重 |
| SkillEvidence | career_evidence | 按账户和技能建立复合外键，证据带有来源、说明、链接和证据等级 |
| CareerGoal | career_goals | 目标方向、期望成果、日期、状态 |
| AssessmentResult | career_assessments | 测评种类、简要结果、完成时间；每次完成独立归档 |
| ResumeVersion | career_resumes | 引用原简历模块的文档 ID，仅保存版本元数据，不复制私有文件路径 |
| 修改历史 | career_revisions | 手动记录每次创建、修改、删除时的实体快照 |

画像由关系查询聚合成 API 响应；响应 JSON 不是一个可整体覆盖的持久化对象。历史表中的 JSON 仅用于保存单个实体当时的版本。

## 证据规则

证据等级为 `self_report`（用户自述）、`experience_support`（经历支持）、`artifact_verified`（成果验证）、`assessed`（实际评估）。技能等级由已有证据的最高等级计算。

用户可提交自述和经历支持材料。经历支持必须包含具体说明。项目链接仅作为材料，不自动触发核验、不提升为成果验证。后两级已预留，但当前版本未提供人工验收、代码执行或面试评分服务，也没有允许用户自行设置这些等级的接口。生涯助手收到的档案上下文包含这些等级，并明确限制从技能名称推断胜任能力。

## 既有资料的接入

- 简历：读取原简历模块当前文档和历史文档元数据；从结构化简历中提取技能和教育、项目条目。简历技能保守标记为自述，不根据同一份简历中出现项目就推断其已验证。原模块分析结果和文件存储继续有效。
- 测评：自动归档服务端 MBTI、霍兰德的已完成历史；打开职业档案时同步当前登录账户在此浏览器中的六类测评简要历史。按测评类型和完成时间去重，不复制答题明细。
- Chat Memory：实时读取该账户当前有效或冲突的事实记忆；不复制进新的长期记录。更正、删除记忆后，重新读取档案即可反映变化；冲突记录显示待确认。
- 手动档案：按条目维护，供生涯助手在允许引用工作台资料时读取。助手暂停引用简历后，新增档案上下文会排除简历来源条目。

外部来源条目在原模块维护。删除简历时，会删除关联的版本元数据、简历来源证据和条目；没有剩余证据的简历技能外壳也会移除。本人另外填写的证据继续保留。删除账户通过外键级联清理档案和历史。

## API 与并发

- `GET /api/career-profile`：聚合本人的档案及当前记忆线索，幂等同步既有简历与测评来源。
- `PUT /api/career-profile/profile`：维护本人基础画像。
- `POST /api/career-profile/{entries|skills|evidence|goals}`：创建独立记录。
- `PUT /api/career-profile/{type}/{id}`：更新单条记录，需提交读取时的 `version`。
- `DELETE /api/career-profile/{type}/{id}`：移除本人手动记录，需提交 `version`；技能仍有简历来源时，需先处理原来源。
- `POST /api/career-profile/assessment-import`：同步当前账户的浏览器测评历史，最多 50 条。
- `GET /api/career-profile/history/{id}`：读取本账户实体的最近 50 次变更。

输入通过 Pydantic 校验；不接收客户端指定的账户或来源。写操作沿用登录会话与 CSRF 校验；读取与关联查询都限制当前账户，私有响应禁止缓存。版本冲突返回 409，避免多个窗口互相覆盖。

## 验证

运行 `npm run check:profile` 检查账户隔离、证据等级、来源删除、历史去重、并发版本与级联清理。运行 `npm run build` 构建前端；`node frontend/scripts/check-learning-path.mjs` 验证保留的学习路径能力。
