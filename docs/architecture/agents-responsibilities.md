# 智能体职责与页面对应关系

更新日期：2026-10-16。本文依据当前项目代码整理，描述已经实现的职责、调用关系和页面入口。

## 1. 整体结构

项目的核心多智能体流程由 **6 个专业分析角色和 1 个报告写作环节**组成，主要在用户点击“规划报告 → 启动生成”后执行。

各角色使用不同的系统提示词、输入材料和输出结构，由后端统一调度，可以共用同一个模型。它们并不对应七套独立部署的模型，也没有各自独立的聊天窗口。

测评、简历输入、职业访谈和岗位浏览提供分析材料；多智能体流程在这些材料的基础上形成职业建议，最终汇集到报告中心。

## 2. 核心智能体职责

| 智能体 | 主要输入 | 职责 | 主要输出 | 页面与成果位置 |
| --- | --- | --- | --- | --- |
| 行业分析师 | 专业、目标方向、目标城市、近期新闻上下文 | 分析行业趋势、需求变化、能力投入优先级及风险 | 行业摘要、升温与降温方向、技能优先级、风险信号、验证建议 | “规划报告”的行业分析节点；报告中的宏观就业环境、趋势与风险分析 |
| 职业定位顾问 | 用户画像、测评与意愿、行业分析摘要，以及可选的画像相关资讯摘录 | 提出适合探索的职业方向，明确硬约束和需要经历证据验证的方向假设 | 推荐方向、待验证假设、硬约束、用户意愿摘要 | “规划报告”的职业定位节点；报告中的个人特质、职业方向和定位结论 |
| 简历证据分析官 | 简历原文；复核时追加职业定位假设 | 从项目、实习、竞赛、证书等经历中提取能力证据，并检查证据是否支持目标方向 | 技术技能、通用能力、方向假设支持情况、证据缺口 | “规划报告”的简历证据解析与证据复核节点；报告中的经历依据、能力证据与附录 |
| 能力评估官 | 简历证据、职业方向、必要时补充简历节选 | 基于证据形成就业能力画像，识别优势、短板和无法判断的维度 | 能力维度、优势、差距、未知项 | “规划报告”的能力评估节点；报告中的能力分析和差距分析 |
| 岗位匹配官 | 能力画像、候选岗位及其要求、职业定位、行业摘要 | 将用户能力与岗位要求对齐，解释匹配情况、硬门槛和待补能力 | 目标岗位、匹配分数与等级、硬性缺口、部分差距、权重说明 | “规划报告”的岗位匹配节点；报告中的目标岗位分析、人岗匹配与决策建议 |
| 路径规划师 | 职业定位、岗位匹配差距、能力评估、行业信息、简历证据、毕业时间 | 将目标与差距转成长期方向、中期里程碑、短期行动和备选路线 | 愿景岗位、阶段里程碑、行动依赖、备选方案 | “规划报告”的路径规划节点；报告中的成长路径、行动计划和风险管理 |
| 报告写作／总编辑 | 六个专业角色的输出、岗位材料、阶段计划 | 按章节整理、去重、衔接并生成完整职业报告 | 八章报告正文、章节内容及相关汇总 | “规划报告”的报告合成节点；报告中心的完整报告及导出文件 |

上述输出会在后端组成报告数据包。主要字段包括 `industry_brief`、`positioning_output`、`resume_evidence`、`competency_profile`、`match_output` 和 `path_plan`。这些字段并不意味着前端为每个角色都提供了独立结果页。

## 3. 实际执行顺序

1. **整理输入**：取得用户画像、简历、测评、访谈、候选岗位及新闻上下文。
2. **并行分析**：在模型模式下，行业分析师与简历证据分析官的第一轮分析并行执行，同时可以准备画像相关资讯检索。
3. **职业定位**：结合用户画像和行业分析生成方向假设。该步骤可以在简历第一轮分析仍在执行时开始，并不直接依赖第一轮证据输出。
4. **证据复核**：当职业定位生成了需要验证的假设时，再调用简历证据分析官复核；没有对应假设或处于降级模式时，复用第一轮结果。
5. **能力评估**：基于证据构建能力画像。
6. **岗位匹配**：对齐能力画像与岗位要求，形成匹配结论和差距项。
7. **路径规划**：围绕差距生成分阶段行动与备选路径。
8. **报告合成**：整理结构化结果，按章节生成报告；配置允许时尝试生成宏观环境配图。

行业分析使用近期新闻摘要上下文。画像相关的资讯检索结果属于可选材料，主要注入职业定位环节，不是独立的分析智能体。

当前实际报告编排调用 `run_report_section_writer()` 逐章写作。代码中还保留了 `run_report_editor()`，但它不是当前主流程使用的报告写作入口。

未配置可用模型时，报告流程会采用规则或模板降级输出；部分并行任务也有超时回退。因此，页面显示阶段完成，不等于该阶段一定成功调用了模型。

## 4. 为什么流程图有九个节点

前端协作图包含以下九个节点：

| 节点 | 对应性质 |
| --- | --- |
| 画像输入 | 输入汇总阶段，不是额外的分析智能体 |
| 行业分析师 | 专业分析角色 |
| 简历证据分析官 | 第一轮证据分析 |
| 职业定位顾问 | 专业分析角色 |
| 证据复核 | 同一位简历证据分析官的第二轮工作，按条件执行 |
| 能力评估官 | 专业分析角色 |
| 岗位匹配官 | 专业分析角色 |
| 路径规划师 | 专业分析角色 |
| 报告合成 | 报告整理与写作环节 |

因此，“九个流程节点”“八个后端进度阶段”和“六个专业角色加一个写作环节”是不同的计数口径。后端阶段列表没有单列前端的“画像输入”节点。

协作图是阶段示意，具体并行方式和数据依赖以报告编排代码为准。代码中保留的旧版阶段名称用于兼容历史报告，不应再计为一组正在独立运行的智能体。

## 5. 各页面承担什么工作

| 页面／板块 | 当前工作 | 与核心智能体的关系 |
| --- | --- | --- |
| 智能仪表盘 | 展示概览、新闻快报和流程入口 | 提供行业信息和功能入口；新闻采集与展示本身不是行业分析师 |
| 岗位探索 | 浏览岗位样本、招聘快照、职业与行业分类，查看城市分析 | 提供数据与参照；浏览列表不会自动运行整套报告智能体 |
| 能力画像 → 测评输入 | 完成基础和补充测评，保存进度及结果 | 为职业定位和画像分析提供材料 |
| 能力画像 → 简历输入 | 上传、解析和诊断简历 | 提供简历结构化材料；该解析流程与报告里的简历证据分析官是不同的调用环节 |
| 能力画像 → 访谈补充 | 通过对话补充经历、价值观和职业意愿 | 生成访谈摘要，补充画像输入 |
| 能力画像 → 统一画像结果 | 汇总测评、简历和访谈，展示画像及相关结果 | 属于独立的画像汇总流程，不能直接等同于报告里的能力评估官 |
| 人岗匹配 | 从职业图谱中计算候选岗位，按配置使用模型调整排序 | 与报告中的岗位匹配官属于两条调用流程 |
| 规划报告 | 启动报告生成并展示协作流程状态 | 核心多智能体流程的主要入口 |
| 报告中心 | 阅读、管理和导出报告，查看行动计划等成果 | 核心智能体产出的主要展示位置 |

## 6. 核心流程之外的 AI 能力

| 功能 | 具体职责 | 入口与实现 |
| --- | --- | --- |
| 职业访谈助手 | 根据测评背景和对话逐步追问经历、价值观及意愿；完成时生成结构化摘要 | 能力画像的访谈补充；`/api/career-interview`、`/api/career-interview/finish` |
| 简历解析与诊断 | 解析简历，提取技能和经历，并提供诊断材料 | 能力画像的简历输入；`/api/resume/upload`、`/api/resume/analyze` 等接口 |
| MBTI 辅助澄清 | 在维度接近时追加问题，辅助确认倾向 | 基础 MBTI 测评；`/api/mbti-clarifier` |
| 补充测评 AI 解读 | 对补充测评结果生成解读 | 补充测评结果页；`/api/deep-test-analysis` |
| 人岗匹配推荐 | 先按职业图谱规则计算候选岗位，再按模型配置调整排序；模型不可用时保留规则推荐 | 人岗匹配页；`/api/career-graph/match` |
| 画像生成与配图 | 根据已有材料生成画像相关内容或图像 | 能力画像相关操作；`/api/profile-portrait/generate` 等接口 |

基础测评的量表计分由规则完成，AI 澄清与解读是附加环节。新闻抓取、分类数据检索、城市统计和图表绘制同样不应仅因服务于职业分析，就被单独称为智能体。

## 7. 最终报告的八个章节

| 章节 | 主要内容来源 |
| --- | --- |
| 一、执行摘要 | 职业定位、匹配结论及各角色的关键判断 |
| 二、宏观就业环境 | 行业分析师 |
| 三、个人特质与潜力 | 用户测评与画像、职业定位、简历证据、能力评估 |
| 四、目标企业与岗位分析 | 岗位数据、岗位匹配与行业分析 |
| 五、人岗匹配与决策建议 | 岗位匹配官、职业定位顾问 |
| 六、差距分析与行动计划 | 能力评估、岗位匹配差距、路径规划 |
| 七、风险管理与备选方案 | 行业风险、定位约束、路径规划的备选方案 |
| 八、附录 | 经历证据、资料与验证建议等 |

章节由报告写作环节统一组织，并非一个智能体只负责一个固定章节。
