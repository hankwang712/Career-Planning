# 报告内容与质量检查

职业报告的正文用于帮助用户理解选择依据并执行下一步。Agent 的原始结果负责保留证据和执行状态，不应直接充当正文。

## 正文如何组织

- 个人信息优先使用本次简历中有原文依据的职业画像，补充已填写的资料；没有信息的字段不逐项显示“未提供”。
- 阅读版按核心结论、个人经历、岗位适配、近期行动、成长与调整、参考依据组织为六部分，不固定展开十章。
- 岗位适配使用连贯段落，重点解释两项已有支撑和三项近期准备重点；影响资格判断的条件全部保留。完整检查项保留在分析数据中。
- 正文不逐项显示“要求编号／支持状态／引用原文”，只在附录保留每个来源的一段代表性引文；没有可靠统计时不单列行业分析。
- 近期行动按周保留任务、预计工时、成果和完成标准。零支出、无依赖、阶段标签等默认字段不输出；真实支出和前置依赖仍说明。
- 个人经历不显示简历诊断分数、空白资料字段或整套简历问题清单，避免与适配分析和行动章节重复。
- 来源使用企业、岗位和城市名称。正文不输出检索片段哈希、本机路径、数据库记录号或结构字段赋值。
- 无关岗位的排除记录不作为核心要求展开；真实工作形式、到岗安排等条件仍需保留。
- 成长部分用段落解释各阶段重点与调整条件，不重复列三套交付物和验收字段。没有成长路线时不填模板；相同阶段内容只呈现一次。
- 调整条件与时间不足的取舍并入成长部分，样本范围集中说明一次，不把各 Agent 的限制原样拼接。
- 未回复的问题以最终决策的有效追问为准；已回答的问题不再次作为待办列出。

原始 `agent_results`、引用来源、检查项与任务关联编号仍保存在报告数据中。任务板使用原 ID 保持进度关联，用户看到的标题和说明使用可读措辞。

## 上游生成约束

岗位相关性按真实职责判断：标题为 Python 实习生但实际开发 RAG 引擎的岗位，不因标题不同就自动排除；有 Python 关键词的硬件岗位也不能直接并入 Agent 能力要求。

明确排除的岗位形式不应继续主导用户的学习差距。每次追问只核实一个事实，复合问题的一句肯定回答不能确认所有能力。已声明的独立开发不再默认存在团队贡献不明，技能缺少项目举例不直接等同于虚构或建议删除。

教育时间使用明确年月进行比较。对于材料中已经说明的“本科结束月份早于计划入学月份”，若模型仍将两者写成重叠，简历分析、职业决策和主站行动规划会返回校验错误，复用已有的修正与重试流程。计划入学也不能当作已取得研究生学历。

## 验证范围

运行 `npm run check:report`，涵盖工作流及内容回归。新增内容检查覆盖内部标记隔离、来源可读性、资料一致性、限制去重、原始证据保留及教育日期误判修正。

这些检查能防止明确的结构与日期错误，不能证明所有语义判断都正确。岗位相关性、拒绝岗位后的技能取舍、建议是否适合用户等仍需结合真实案例评估。历史报告不会因修改生成代码而自动改写，需要重新生成后复核。

阅读版使用 `reading_layout=narrative-v1` 标识。完整性检查按新的章节和已有证据、行动数据检查，不要求凑够旧版字数或重新补出被合并的章节；历史报告沿用原来的兼容规则。

网页阅读版按同一章节顺序显示正文，不再用空的结构化数据生成额外的评分、状态卡片或模块占位说明。`npm run check:report-development` 同时覆盖这些展示约束。
